# Durable Submissions Implementation Plan

**Goal:** 新增交件幂等去重，交件与到账待确认提交跨刷新保留并可核对、安全重试。
**Architecture:** SQLite事务中保存交件请求指纹和记录引用；到账复用原ID。浏览器localStorage以提交ID分别保存待确认内容，收到确认才清除。只读核对接口不补交；取消在服务器写入取消标记，阻止迟到请求。恢复账本更换提交代号，旧待确认内容不能自动写入恢复后的账本。
**Tech Stack:** FastAPI/Pydantic、SQLite、原生JS、localStorage。
**Spec:** 本聊天用户已批准交件唯一标识、刷新持久化、先核对再重试、内容冲突拒绝、删除/作废不复活方案。

## Constraints / review focus
- 保留现有未提交修改，不部署、不修改真实账本。
- 同一请求同内容只创建一次；不同内容409；不同ID同内容允许正常多笔。
- 原始输入指纹不受默认价调整或记录编辑影响；备份包含去重和取消记录，旧备份兼容。
- 保存成功响应丢失、并发、刷新、月份锁、删除/作废和恢复账本都要明确处理。
- 浏览器存储不可用时拒绝发起新持久提交；不自动重放，不静默覆盖未决内容。
