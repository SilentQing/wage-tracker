# 计件交件与工时薪资核算系统（Wage Tracker）

面向个人车间交件与加班记账的轻量 Web 应用。采用 FastAPI、SQLite 和原生 JavaScript，页面、脚本与 CSS 均由同一服务提供，支持手机浏览器和飞牛 NAS Docker 部署。

## 核心功能

- 按日期记录零件、数量、交件单价和备注，支持编辑、筛选、删除及恢复。
- 已有零件通过下拉菜单选择，也可手动录入新名称。默认内置“定距筒”。
- 每条交件保存自己的单价，后续调整类别默认单价时，已定价的历史交件保留原价。
- 日历勾选加班，支持补记、取消、今日快捷记录、每天独立时长和补贴，以及周一至周日的整周统计。
- 按月维护上班天数、正班日工时和默认加班参数，“全部累计”按各月考勤合计。
- 每月可启用每日出勤：每天 8.5 小时、无固定周休日，截至今天默认出勤，只需记录全天、半天或自定义小时请假。
- 不合格扣件保留提交数量，按原记录单价核算计薪数量；月底手动确认 100 元全勤奖。
- 工资按所属月份对账，支持跨月分次到账、差额提示和错误到账作废。
- 月份结算锁定、最近20次修改日志、CSV 导出、完整 JSON 备份与恢复。
- 每天北京时间 03:00 本地备份，重启补备份，保留 30 份定时备份；支持恢复检查、下载及恢复前预览。WebDAV 仅预留接口。
- 可配置密码保护，运行时加载本地 CSS，Docker 构建时安装固定版本依赖。

## 日常使用

1. 选择工资所属月份，维护零件默认单价，录入每天交件数量；需要时填写本条单价。
2. 在“每日出勤与请假”中点击“本月启用每日出勤”。每月启用一次，之后只需补记请假；旧月份不自动改变核算方式。
3. 在加班日历勾选实际加班日期，时长或补贴不同的日期单独调整。
4. 收到不合格反馈时，在对应交件行点击“扣件”，填写累计不合格数量及原因。
5. 月底核对出勤和交件，确认是否获得 100 元全勤奖，再锁定月份。锁定不代表工资已到账。
6. 发工资时选择其所属月份，登记实际到账日期及金额；可分次到账，直到差额核对完成。
7. 在“定时备份与恢复检查”查看最近成功时间，必要时立即备份并下载保存。

## 核算规则

交件金额按该条记录的计薪数量（提交数量减不合格数量）乘以记录单价计算，使用十进制运算，逐条四舍五入到分后合计。类别汇总、顶部统计和 CSV 使用同一组记录金额。扣件金额为原提交金额与合格计件金额之差，避免分别舍入产生一分钱差异。

总收入（应发）为合格计件金额加加班补贴、已确认的全勤奖。平均日薪为应发除以上班天数。实际时薪为应发除以正班总工时与加班总工时之和。分母为零时显示零。到账记录不改变应发收入、日薪或时薪。

### 不合格扣件、全勤奖与工资到账

- 在交件明细点击“扣件”，填写该条交件的累计不合格数量和原因；原提交数量保留，填 0 撤销扣件。不合格数量不得超过提交数量，修改提交数量也不能低于已扣数量。扣件跟随该条交件的单价快照，修改类别默认价格不会改变已定价记录。删除交件后整条退出核算，恢复时扣件一并恢复。
- 每月最后一天及以后，可在“工资到账对账”中手动确认获得 100 元全勤奖或确认无奖。系统不根据默认出勤推断全勤；未确认暂计 0 元并显示提示。
- 选择工资所属月份后登记实际到账日期、金额和备注，可以分多次、跨月到账。系统显示应发、累计到账、未到账差额及未到账／部分到账／已结清／超额到账状态。有待定价或未确认全勤奖时，状态仅代表当前已记金额。
- 月份锁定后禁止修改扣件和全勤奖，但可以继续登记到账。录错到账可作废后重录；作废记录保留，退出到账合计。同一页面请求重试使用同一请求标识防止重复入账；刷新后重录前应先核对列表。
- “全部累计”按工资所属月份累计，多发和少发可能抵消，应逐月核对。完整 JSON 备份包含扣件、全勤确认和到账记录；旧备份缺少这些表时按空表恢复。交件 CSV 增加不合格数量、计薪数量、扣件金额及原因。

### 考勤累计与旧数据

“全部累计”的上班天数为各月上班天数之和，正班总工时为各月正班工时之和。启用每日出勤的月份使用每日 8.5 小时减请假后的结果；未启用的月份保留手填考勤。未启用且未保存过考勤的旧模式月份，以有交件的日期数推算上班天数，每天按 8 小时计算，使用前需核对或明确切换到每日出勤。

更早版本若保存过名为 `ALL` 的汇总考勤，原数据会保留并随完整备份导出，页面会提示核对。因为无法确定它与各月数据的重叠关系，当前累计统计按各月求和；旧汇总中的次数和工时需要人工分配到对应月份。

### 单价与旧账本升级

首次升级会为旧交件增加单价快照。旧系统没有保存历史单价，迁移只能使用升级时类别表中的现价，更早的真实价格需要核对后通过“编辑”更正。

- 原有有效正单价会写入历史交件，后续调价保留该价格。
- 旧交件没有价格，或者类别默认价为零时，保留为待定价，金额暂按零计算。
- 修改类别默认价为正数，会为该类别尚未定价且未锁定月份的交件补价，并用于之后的新交件。
- 交件录入时可以填写本条单价，包括明确的零元。编辑时留空会保留原价；变更零件类别且留空时使用新类别默认价。
- 首次添加旧交件价格快照之前，自动把原数据库备份到 `data/backups/before-price-migration-*.db`。

升级会清理旧版默认生成且没有任何交件关联的“庆祝”类别。已有交件关联时保留类别和记录，核对后可改名。目标名称已存在时拒绝改名，避免意外合并账目。

## 出勤、请假与加班

### 每日出勤与请假

选择月份，在“每日出勤与请假”中点击“本月启用每日出勤”。启用后每天默认正班 8.5 小时，周六、周日不休息；只计算截至服务器今天的日期，未来日期不累计。既有月份不会自动切换，新月份也需启用一次。

点击日期可记录全天（8.5 小时）、半天（4.25 小时）或自定义请假小时；选择“恢复出勤”保存 0 小时即可清除请假。正班工时为已过日历天数乘 8.5 减请假小时；出勤天数按正班工时除以 8.5 折算，日薪以此为分母。加班时长及补贴仍单独计算。

启用后原月度手填考勤保留，但正班核算以日历为准，页面禁用手填天数和正班日工时。每月加班默认值仍可调整。结算锁定会冻结出勤计算截止日，并阻止请假变更；解锁后恢复动态累计。完整 JSON 备份包含每日考勤模式、截止日及请假记录；旧备份恢复后保留旧考勤模式。请使用新版本程序恢复新格式备份。

### 加班日历

1. 选择月份后点击日期，或使用“今日加班”。再次点击已勾选日期可取消。支持补记过去日期，每天最多一次，未来日期不可记录。
2. 默认使用所属月份的单次时长和补贴，初始为2.5小时和10元。
3. 某天实际时长不同时，点击“调整某天时长/补贴”，选择日期并保存实际数值。设置为零同样有效。勾选“恢复按所属月份默认设置计算”可清除当天覆盖值。
4. 每周按周一至周日统计完整日期范围、次数、时长和补贴。跨月的一周包含相邻月份记录，月度核算只计入本月日期。
5. 修改月份默认参数会重新计算使用默认值的日期；已填写当天独立数值的日期保留其数值。

旧版只有月度加班次数，升级后显示为“未分配日期的历史加班”，继续参与月度核算，无法自动归入某一天或某一周。

给这些历史次数补日期时，先勾选“将本月1次未分配日期的历史加班转为日期记录”，再点击日期。新增日期和扣减历史次数在同一事务内完成，重复请求只转换一次。新发生的加班直接勾选即可。“今日加班”和独立时长编辑会新增日期记录，不自动扣减历史次数。

取消日期记录会减少一次加班。需要改回未分配日期的次数时，可手动增加历史次数。浏览器按本地日期显示，服务器按系统日期检查未来日期，部署时应保持 `Asia/Shanghai` 时区。

## 编辑、删除与结算

- 点击交件行的“编辑”，在上方录入区修改日期、名称、数量、备注或记录单价后保存。
- 删除交件后可在“已删除交件（当前周期）”中恢复，原单价会一并保留。
- 明细搜索可按日期、名称和备注筛选。筛选只影响明细，顶部核算与 CSV 仍以所选完整周期为准。
- 核对月份后点击“结算锁定本月”。该月交件、考勤和加班的新增、修改、删除、恢复都会被后端阻止，解锁后可继续修改。
- 有待定价交件的月份无法结算。类别关联已锁定月份时无法改名。默认单价仍可更新，已锁定账目使用其记录快照。
- 全勤奖未确认不会阻止锁定，请在锁定前核对；锁定后若要补确认，应先解锁。到账登记与作废不受月份锁影响。
- 修改日志显示最近20条操作，完整日志随 JSON 备份保存。

## 导出、备份和恢复

“导出交件 CSV”和“导出加班 CSV”按当前月份或全部累计导出。CSV 使用带 BOM 的 UTF-8 编码，并处理名称、备注等文本的公式前缀，便于用表格软件查看。

“下载完整备份”生成包含交件、已删除交件、类别价格、各月考勤、每日出勤模式、请假、加班日期、不合格扣件、全勤确认、到账及作废记录、月份锁和修改日志的 JSON 文件。备份包含个人账目，请自行妥善保存。

“恢复完整备份”接受本项目当前格式的 JSON 文件，页面及服务器均限制文件大小为64MB。先在临时数据库试恢复并预览生成时间、月份、记录数量、应发及到账金额，再确认覆盖完整账本。服务器在正式恢复时再次检查，先保存当前账本到 `data/backups/before-restore-*.json`，随后在单个数据库事务中恢复。字段校验失败、数据重复或引用冲突时，原账本保持完整。

自动生成的备份保存在部署设备上。页面下载的备份可另存到其他设备。恢复会使用备份中的月份锁状态。

### 定时备份与恢复检查

应用启动后启用后台备份服务，每分钟检查一次，按北京时间每天 03:00 生成一份 JSON。首次启动或停机错过计划时补最近一期当前快照，不虚构停机期间每天的历史快照。多个服务进程通过独立 `backups/backup-control.sqlite3` 串行执行，已完成的计划不会重复执行。服务停止期间不会运行备份。

文件保存在数据库同级的 `backups/` 目录（默认 `data/backups/`）。每份定时或手动备份都有 `.meta.json` 校验记录。备份执行字段及引用检查、临时 SQLite 试恢复、记录数量与源账本核算比较，序列化后再次试恢复，写入磁盘后检查 SHA256。任何检查失败均不会标记成功或清理旧备份；后台一分钟后重试，页面显示错误。

只保留最近 30 份定时备份；手动备份、迁移备份及恢复前安全备份不参与自动清理。页面提供最近成功时间、错误、下次计划、文件列表、立即备份、下载及重新检查。重新检查先核对原 SHA256，再试恢复；下载也检查摘要。检查不改动当前账本。备份及其 `.meta.json` 应一起保留，控制库保存计划及状态，不随账本恢复回滚。

WebDAV 仅预留 `backup_service.WebDAVAdapter.upload(path, sha256)` 扩展接口和 `.env.example` 中的 URL、用户名、密码变量，当前没有上传实现，不会连接远端，配置凭据也不会自动上传。以后实现时应将远端结果与本地备份结果分开，远端失败不能删除本地备份。当前只在服务器本地保存。

## 密码保护

设置非空的 `WAGE_PASSWORD` 即可启用 HTTP Basic 密码验证，默认用户名为 `admin`，也可通过 `WAGE_USERNAME` 修改。保护范围包含页面、静态文件、接口、下载和 API 文档。环境变量留空时继续使用免登录模式，页面会显示当前状态。

Docker 部署可复制 `.env.example` 为 `.env`，填写自用用户名和密码后重建容器。systemd 部署可在服务环境中配置相同变量并重启服务。密码文件已列入 Git 忽略规则。

公网访问应通过 HTTPS 反向代理传输登录凭据。反向代理应保留外部 Host，应用会拒绝 Origin 与当前 Host 不匹配的跨站修改请求。

## 本地运行

要求 Python 3.11 或更新版本。在项目根目录创建独立环境并运行，以下命令适用于 Windows PowerShell。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn app:app --host 127.0.0.1 --port 8000
```

浏览器访问 `http://127.0.0.1:8000`。应用运行时使用本地样式，无需访问 Tailwind CDN。

修改 HTML 或脚本中的样式类后，重新构建 CSS，需安装 Node.js。

```powershell
$styleInput = Join-Path $env:TEMP 'wage-tracker-tailwind.css'
"@tailwind base;`n@tailwind components;`n@tailwind utilities;" | Set-Content -LiteralPath $styleInput
npm exec --yes --package=tailwindcss@3.4.17 -- tailwindcss -i $styleInput --content './templates/index.html,./static/*.js' -o './static/app.css' --minify
```

## 飞牛 NAS 与 Docker 部署

1. 将仓库源码放入 NAS 项目目录，例如 `/vol1/1000/docker/wage-tracker`。保留 `Dockerfile`、`requirements.txt`、`app.py`、`backup_service.py`、`templates/`、`static/` 和 `docker-compose.yml`。
2. 按需配置 `.env` 中的访问密码。
3. 在飞牛 Docker 的 Compose 中选择该目录构建并启动，或在项目目录执行下列命令。

```sh
docker compose up -d --build
```

浏览器访问 `http://NAS局域网IP:8095`。`./data` 持久挂载到容器，依赖在构建镜像时安装，正常启动不再安装依赖。

升级前备份整个 `data/` 目录，更新源码后重新构建镜像并创建容器。构建需要联网获取基础镜像和依赖，本次仓库改动尚需在目标 Docker 环境验证。

## VPS 更新

仓库原有部署记录为 systemd 服务 `wage-tracker.service`，程序目录 `/opt/wage-tracker`，数据库 `/opt/wage-tracker/data/wage.db`。实际更新前先核对目标机器配置。

1. 在独立源码目录执行 `git pull --ff-only` 并确认提交。
2. 停止服务，备份应用、数据库、环境配置和服务文件。
3. 同步 `app.py`、`backup_service.py`、`templates/`、`static/` 和 `requirements.txt`，保留原有数据目录，使用原虚拟环境执行 `pip install -r requirements.txt`。该版本要求 Python 3.11 或更新版本。
4. 配置访问密码后启动服务，检查原交件、单价快照、出勤、加班、扣件、全勤奖与到账对账；确认备份状态显示启动补备份成功，并试下载、预览一份备份。
5. 若需回滚，停止服务后一起恢复原程序与数据库备份。
