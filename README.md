# ⚙️ 计件交件与工时薪资核算系统 (Wage Tracker)

专为车间计件交件设计的轻量级 Web 记账与薪资核算工具，支持**飞牛 NAS (fnOS)** Docker 一键部署。采用 **FastAPI + SQLite + TailwindCSS**，后端、页面与交互脚本分文件维护，由 FastAPI 统一提供服务，数据本地持久化落盘，手机与电脑局域网打开浏览器即可随时录入。

## ✨ 核心功能

- **交件记录管理**：按日期记录上交的零件种类（默认内置“定距筒”、“庆祝”，支持自由新增与一键改名）、数量及批次备注。
- **未定价智能提醒**：当记录中出现尚未设置单价的新零件种类时，顶部自动弹出醒目横幅提示补全单价。
- **自动薪资与工时核算**：
  - **计件工资**：各零件交件数量 × 对应单价之和
  - **加班总工时**：加班次数 × 所属月份的单次加班时长（默认 2.5 小时/次，可调整）
  - **加班总补贴**：加班次数 × 所属月份的单次加班补贴（默认 10 元/次，可调整）
  - **当前总收入**：计件工资 + 加班总补贴
  - **平均日薪**：当前总收入 ÷ 当月上班天数（支持一键按有交件记录的日期数自动填入天数）
  - **实际时薪**：当前总收入 ÷ (上班天数 × 每日正班工时 + 加班总工时)
- **按月独立账本**：零件单价全局共享，交件明细与考勤参数按月份独立核算，同时支持“全部累计”汇总视图。
- **加班日历**。点击日期记录加班，支持补记、取消、“今日加班”快捷操作和每周汇总，每天最多记录一次。

## 加班日历使用

1. 在“加班日历”选择月份，点击当天日期，或点击“今日加班”。保存成功后日期显示 `✓ 2.5h`，加班次数、工时、补贴和薪资统计同步更新。
2. 昨天或更早的日期忘记记录，可以切换到对应月份，点击该日期补记。再次点击已勾选日期可取消，未来日期不可勾选。
3. 每周按周一至周日统计，列出完整日期范围、加班次数、时长和补贴。跨月的一周包含相邻月份的数据，各日期使用其所属月份的时长和补贴设置。月度核算只计入本月日期。
4. “全部累计”汇总各月的已记日期和历史次数。日历查看、考勤参数修改需要先选择具体月份。

### 旧账本与历史补记

升级后首次启动会自动创建 `overtime_days` 表。原有月度加班次数保留在“未分配日期的历史加班”中，继续参与月度核算。由于旧数据没有日期，这部分无法显示在某一天或归入某一周。

- 记录新发生的加班时，直接点击日期，月度次数会增加一次。
- 给已有历史次数补日期时，先勾选“将本月 1 次未分配日期的历史加班转为日期记录”，再点击日期。系统在同一事务中新增日期并扣减一次历史次数，月度总次数保持一致。
- 取消某个日期记录会减少一次月度加班。若要把它重新归为未分配日期的历史次数，可手动增加上方历史次数。
- 同一天重复勾选或请求重试会保留一条记录，历史转换也只扣减一次。

每个日期使用所属月份当前设置的单次时长和补贴。修改这些设置会重新计算该月全部加班记录。默认每天一次，每天的实际加班时长暂不单独填写。浏览器使用本地日期，服务器依照其系统日期校验未来日期，部署时应使用 `Asia/Shanghai` 时区（Compose 已配置）。

## 项目结构

```text
wage-tracker/
├── app.py                 # FastAPI 接口与 SQLite 数据库操作
├── templates/
│   └── index.html         # 页面结构
├── static/
│   └── app.js             # 页面交互、接口请求与薪资展示计算
├── docker-compose.yml     # NAS Docker 部署配置
├── tests/
│   └── test_overtime.py   # 加班日期、跨月统计与旧账本兼容回归测试
└── data/
    └── wage.db            # 运行时生成的本地数据库
```

浏览器通过 `/api/` 接口读写数据，通过 `/static/app.js` 加载交互脚本。首页和静态文件均由 FastAPI 提供，修改页面或脚本后刷新浏览器即可加载。

## 本地运行

在项目根目录创建独立虚拟环境并启动服务。以下命令适用于 Windows PowerShell。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install fastapi uvicorn pydantic
.\.venv\Scripts\python.exe -m uvicorn app:app --host 127.0.0.1 --port 8000
```

打开浏览器访问 `http://127.0.0.1:8000`。数据库路径为相对启动目录的 `data/wage.db`，日常启动时应保持项目根目录为工作目录。

### 回归检查

在上述独立虚拟环境中安装测试客户端并运行测试。

```powershell
.\.venv\Scripts\python.exe -m pip install httpx
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

测试使用临时 SQLite 数据库，覆盖补记、取消、重复及并发请求、历史次数转换、跨月统计、零补贴和旧数据库升级。

## 🚀 飞牛 NAS (fnOS) 部署步骤

1. 在飞牛 NAS 文件管理中新建文件夹（如 `/vol1/1000/docker/wage-tracker`），放入 `app.py`、`docker-compose.yml`，以及完整的 `templates/` 和 `static/` 目录。
2. 打开飞牛 **Docker** → **Compose** → **新增项目**，选择该文件夹路径并启动。
3. 浏览器访问 `http://你的飞牛NAS局域网IP:8095` 即可使用。
4. 所有数据自动持久化保存在 `./data/wage.db` 中。

升级已有部署时，需要一起更新 `app.py`、`templates/`、`static/` 和 `docker-compose.yml`，随后重新创建 Compose 容器，使新增目录挂载生效。`data/` 保存实际账本，更新前先备份该目录。

## GitHub 维护与 VPS 更新

本仓库的初始应用源码来自用户提供的新版压缩包。后续开发以 GitHub 提交记录为准。

`data/`、SQLite 数据库、虚拟环境、环境变量文件和备份已列入 Git 忽略规则。工资记录保存在部署设备上。

现有 VPS 使用 systemd 管理 `wage-tracker.service`，应用位于 `/opt/wage-tracker`，数据库为 `/opt/wage-tracker/data/wage.db`。上面的 Compose 配置用于 NAS 部署。

VPS 后续更新按以下流程执行。

1. 本仓库为公开仓库，可通过 `git clone https://github.com/SilentQing/wage-tracker.git` 检出到独立的源码目录，无需配置 GitHub 登录凭据。
2. 在源码目录执行 `git pull --ff-only`，确认要部署的提交。
3. 停止应用服务，将现有应用（包括页面与静态文件）、数据库和服务配置备份到带时间戳的独立目录。
4. 将选定提交的 `app.py`、`templates/` 和 `static/` 一起部署到 `/opt/wage-tracker`，保留原有 `data/` 和虚拟环境。若依赖有变化，按该提交的部署说明更新依赖。
5. 启动服务，检查服务状态、网页响应、原有记录与工资计算。验证失败时使用对应备份恢复。

GitHub 仓库导入与 VPS 生产更新分别执行。服务器的更新命令和回滚步骤将在首次从 GitHub 部署时实机验证。
